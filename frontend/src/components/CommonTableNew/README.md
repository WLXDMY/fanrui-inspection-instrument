### 组件应该传入的参数有哪些

1. `data`
   
   - 类型： `Array`
   
   - 是否必传： **是**
   
   - 说明：这个参数是组件的数据来源。

2. `allComumns`
   
   - 类型：`Array`
   
   - 是否必传：**是**
   
   - 说明：这个参数是表头配置的数据来源,一般只需要传入constant.js 内的数据即可，接下来的更新或者保存，组件已经帮助你操作了，无需自己再做其他配置。

3. `columnPermissionAction`
   
   - 类型：`String`
   
   - 是否必传：**否**
   
   - 说明：这个参数是操作按钮的显示权限，如果不传入，就没有弹出配置表头信息的弹窗。

4. `columnsSaveName`
   
   - 类型：`String`
   
   - 是否必传：**是**
   
   - 说明：这个参数是后台保存表头配置时需要提供的名字，如果不传入，默认名字为 columns 会与其他同样未配置名字的组件一样，造成冲突。

5. `leftSelection`
   
   - 类型：`Boolean`
   
   - 是否必传：**否**
   
   - 说明：配置左勾选框是否显示，默认为 `true`

6. `show-summary`
   
   - 类型： `Boolean`
   
   - 是否必传：**否**
   
   - 说明：是否显示汇总功能（列表最下层的汇总列）。

7. `border`
   
   - 类型：`Boolean`
   
   - 是否必传： **否**
   
   - 说明： 列表是否显示有 border 样式，公司表一般都会加上。

8. `v-loading`
   
   - 类型：`Boolean`
   
   - 是否必传：**否**
   
   - 说明：表请求数据时是否显示loading 图案，公司表一般都会加上。



### 组件有哪些回调方法

1. `@reNewAllComumns` 
   
   - 类型：`Function`
   
   - 是否必传：**否**
   
   - 返回值：`Array`
   
   - 说明： 表头有变动时会触发这个函数，首次进入组件时也会触发一次，所以强烈建议获取后台列表数据的操作在这里进行，而不是在 created 里面获取列表数据。

2. `@updateQueryParams` 
   
   - 类型：`Function`
   
   - 是否必传：**否**
   
   - 返回值：`Object`
   
   - 说明： 表头筛选条件点确定时触发这个函数,返回的值时筛选的条件字段。所以这里应该需要再次调用接口获取后台数据，记得带上筛选条件字段。



### 组件有哪些可用的组件内方法

1. `resetQuery`
   
   - 类型：`Function`
   
   - 返回值：`undefault`
   
   - 说明：这个方法应该通过 类似 this.$ref['common-table'].resetQuery() 这样的方式去调用,调用后，整个表都会重置，表头之前的所有配置都会还原成默认值。如果你已经在@reNewAllComumns 方法中已经调用了后台获取数据接口，这里就不需要重新调用接口了，因为整个方法必然会触发@reNewAllComumns 方法。
